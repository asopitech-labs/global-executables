# Global Executables v1.4.1

This corrective release makes installation guidance distinguish verified,
environment-specific recipes from package-manager syntax alone. For matched
providers and tested targets, `resolve_installation` can report a `ready` recipe
with its install and invoke commands and a link to the verification run. Other
providers and targets continue to report `unverified` or an explicit context or
unsupported outcome. The browser Playground now offers environment and scope
selectors while retaining advanced JSON input.

## Verification

- Published-package install and invoke checks: [GitHub Actions run 39363743911](https://github.com/asopitech-labs/global-executables/actions/runs/39363743911) passed on Debian 13, Ubuntu 24.04, and macOS 15. It exercised apt, Homebrew, npm project/user, and pip virtualenv/user methods against packages currently represented in the dictionary.
- Resolver, MCP, CLI and Playground contract tests: PR #92 (validation run to be recorded after review).

## Data and limits

- The dictionary snapshot and its partial coverage caveats are unchanged from v1.4.0. The broad npm and Go catalog completion work remains tracked separately.
- A verified recipe applies only to its recorded provider, version or repository source, and target. It is not a blanket guarantee for every package that happens to expose the same command name.
